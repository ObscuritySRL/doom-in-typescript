- Design decision: add a thin bridge module `src/assets/wireSpriteFrameCacheFromIwadResourceCache.ts` that consumes an `IwadResourceCache` plus a `wadBuffer` and produces a `SpriteFrameCache` via the existing `buildSpriteFrameCache` primitive. The buffer is passed separately (not retained in the cache) so the bridge stays consistent with the 05-001 intentional decoupling. Failure modes (missing S_START/S_END markers, sprite lump size below patch-header bytes, sprite-name not 4 alpha + frame letter + rotation digit) are surfaced as the underlying `parseSpriteNamespace` / `buildSpriteFrameCache` errors — no new error class is needed since the upstream primitives already produce typed RangeErrors with the offending sprite name.
- The focused test will use the real `doom/DOOM1.WAD` (REFERENCE_BUNDLE_PATH is local-only and gitignored, so the test gracefully skips when the bundle is absent; the shareware WAD's 483-sprite namespace pins the count) plus a synthetic minimal-namespace IWAD to exercise the failure modes. The wrapper exposes a stable signature `wireSpriteFrameCacheFromIwadResourceCache(cache: IwadResourceCache, wadBuffer: Buffer): SpriteFrameCache` and a frozen result.
