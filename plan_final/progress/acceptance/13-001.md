## 2026-05-15 - fix attempt after failed live command
- Root `doom.ts` forwards `Bun.argv.slice(2)`, while `parseCommandLineConfiguration` intentionally treats argv[0] as the program-name slot. The child process therefore parsed `-iwad` as the program name and ignored it, so the root live branch did not run. Updated `runDoomMain` to normalize root-style argv vectors that begin with a flag by prepending a synthetic `doom.ts` program-name slot before parsing.
- Direct probe after the argv fix reached the host path but Bun segfaulted inside user32 message dispatch. Simplified the smoke host to keep presenting the TITLEPIC client-area frame without dispatching Win32 messages; the acceptance test owns process termination after capture.
- The segfault was actually at `AdjustWindowRect`: this Bun build does not expose `Buffer.ptr`, and passing `undefined` to `FFIType.ptr` crashed user32. Updated the smoke host to pass `Buffer` objects directly for pointer parameters. A direct `bun run doom.ts -iwad doom/DOOM1.WAD` probe then stayed alive until the command timeout killed it, confirming the process no longer exits/crashes before window lifetime.
