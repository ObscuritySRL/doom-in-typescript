- Design decision: add a new `src/vanilla/win32WindowHost.ts` wrapper that mirrors the launcher's framebuffer + palette + presentation pipeline without any `LauncherSession` dependency. The wrapper exposes pure-arithmetic primitives (framebuffer allocation, palette-to-BGRA lookup builder, indexed-to-BGRA conversion, presentation-rect delegation, BITMAPINFOHEADER builder) keyed to the vanilla `SCREENWIDTH=320` / `SCREENHEIGHT=200` constants from windowPolicy. The actual Win32 window-creation / GDI present loop is intentionally NOT inlined here (FFI calls can't be unit-tested without a real window); the wrapper provides the building blocks a later step's host bring-up can compose. No `src/host/` file is modified; no `src/launcher/` file is modified.
- Wrote `src/vanilla/win32WindowHost.ts`: exports `VANILLA_FRAMEBUFFER_BYTE_LENGTH = 64000`, `VANILLA_PALETTE_ENTRY_COUNT = 256`, `BITMAP_INFO_HEADER_BYTE_LENGTH = 40`, `createIndexedFramebuffer()`, `buildBgraPaletteLookup(palette)`, `convertIndexedFrameToBgra(source, destination, paletteLookup)`, `buildVanillaBitmapInfoHeader()`, and `computeVanillaPresentationRect(clientWidth, clientHeight)`. The palette lookup packs `0xFF_RR_GG_BB` so a 32-bit read on little-endian produces the byte sequence `B, G, R, A` GDI expects in `BI_RGB` mode. The bitmap-info header uses a negative biHeight to declare a top-down DIB (matching the launcher's convention). The presentation rect delegates to `computePresentationRect(clientWidth, clientHeight, true)` so the Chocolate Doom 2.2.1 `aspect_ratio_correct = 1` default is honored.
